## 一、看之前要知道的四件事

阶段 0 讲了命令;要读懂回放和曲线,还需要知道训练环境里发生的四件事。

**1. 回合与终止。** 一个回合 = 从鸭子被放下到这次尝试结束。走路任务里,回合在两种情况下结束:
- `time_out`(超时):撑满 20 秒(1000 步)。这是"好的结束"。
- `fell_over`(摔倒):躯干倾斜超过 70°。
- 另外两种在平地上不该出现:`nan_state`(物理计算出了无效数值,阶段 0 第五节)和 `out_of_terrain_bounds`(走出地形边界)。曲线面板里它们应恒为 0。

结束后鸭子立刻被重新放下,开始下一个回合。**回放里鸭子倒了又站回原处,就是这个。**

**2. 指令。** 每只鸭子随时带着一条指令,告诉它往哪走:
- 速度指令(twist):前后速度、左右横移速度、转向角速度三个数。训练时每 3–8 秒随机换一次;其中一部分鸭子拿到的是全零指令,也就是"站着别动"。
- 头部姿态指令:头该朝哪,每 2–5 秒随机换一次。**所以回放里头会自己转动,这不是故障。**

策略能看到指令,奖励按它有没有跟上指令来算。

**3. 课程学习。** 训练不是从头到尾用同一套规则,而是随轮数逐步加码。走路任务里,前 2000 轮内有几项按轮数分级变化:
- 动作平滑的惩罚权重从 −0.1 分级加到 −1.0(第 1500 轮到顶)。
- 拿"站着别动"指令的鸭子比例从 2% 分级加到 25%(第 2000 轮到顶)。
- 头部指令的范围、身体参数随机化的范围逐步放宽。
- 纠正低头的惩罚 `head_pose_bias` 第 600 轮启用,第 1000、1500 轮再加码(权重 1 → 2 → 3)。

**曲线在 500、600、750、1000、1250、1500、2000 轮附近出现拐点或台阶,多半是课程在加码,不是训练出了问题。**

**4. 推力。** 训练时每 3–6 秒随机推鸭子一下,逼它学会被推不倒。

### 回放环境 ≠ 训练环境

回放用的环境是训练环境的一个变体,有三处不同,读回放时必须记住:

| 不同点 | 后果 |
|---|---|
| 推力更频繁:每 0.5–1 秒推一次 | 踉跄多半是刚被推了。看的是被推后几步能不能稳住 |
| 课程学习从第 0 级算起,按这次回放累计的步数往上走 | 回放开头的奖励权重是训练初期的值,比如动作平滑惩罚是 −0.1。累计 12000 步(原速约 4 分钟)后开始加码。**Reset Environment 和换存档都不会让它归零,只有重启回放命令才归零。** 所以:回放里的奖励条不能拿去和曲线面板的数值比;在存档之间横向比奖励条时,先重启回放命令 |
| 只有你放的那几只鸭子 | 一只鸭子一次回合只是一个样本。曲线是上千只鸭子的平均。两边对比看趋势,不比数值 |

【"先问清回放环境和训练环境有什么不同"换机器人也一样】

## 二、回放查看器:判读用法

启动方法见阶段 0 第八节。本节讲判读要用的面板。

### Controls(控制)标签页

**Simulation(仿真)**:控制时间。

| 按钮 | 用法 |
|---|---|
| Pause / Play(暂停 / 继续) | 看到怪动作先暂停 |
| Step(单步) | 暂停时每按一次前进一步(1/50 秒),逐帧看它怎么倒的 |
| Reset Environment(重置环境) | 让鸭子回到初始姿态。**换存档后先按一下**,保证每个存档从同一起点比 |
| Speed(速度) | Slower 慢放 / 1x 原速 / Faster 快放。看脚的动作用慢放 |

**Info(信息)**:`Steps`(步数)是查看器启动以来的总步数,**只有手动点 Reset Environment 才归零,摔倒后自动开始的新回合不归零**,所以它不是回合长度。
量回合长度的方法:鸭子刚被放下时 Pause 记下 Steps,下一次被放下时再记,两数相减就是这个回合的步数。

**Commands(指令)→ Twist(速度指令)**:手动给指令。控件名里 lin = linear(直线),ang = angular(角度、转动),vel = velocity(速度)。

| 控件 | 含义 |
|---|---|
| Enable(启用) | 勾上,下面的滑块才生效。**不勾时指令照样由环境随机给**(见第一节),做对比必须勾 |
| lin_vel_x | 前后速度,米/秒,正数向前 |
| lin_vel_y | 左右横移速度,米/秒,正数向左(螃蟹步,不是转弯) |
| ang_vel_z | 转向角速度,弧度/秒,正数向左转 |
| Max lin_vel_x 等(最大值) | 只改滑块的上限。默认值就是训练时的范围:前后 ±0.4、横移 ±0.3、转向 ±1.0。超出这个范围,是在要求它做没练过的事 |
| Zero(归零) | 三个速度一键归零 |

方向都以鸭子自己的身体为准:x 朝它面前,y 朝它左手。**Enable 只管镜头跟着的那一只鸭子**,另一只仍拿随机指令。头部指令不能手动给,一直是随机的。

### Scene(场景)→ Debug Viz(调试可视化):速度箭头

勾上 `Enabled`(启用)和 `Twist`,鸭子头顶出现四根箭头。`All envs`(所有环境)勾上则每只鸭子都画。

| 箭头 | 颜色 | 表示 |
|---|---|---|
| 指令线速度 | 深蓝,水平 | 让它往哪走、多快 |
| 实际线速度 | 青色,水平 | 它实际往哪走、多快 |
| 指令转速 | 绿色,竖直 | 让它转多快,朝上 = 左转 |
| 实际转速 | 亮绿,竖直 | 它实际转多快 |

**读法:看两对箭头是否重合。** 箭头长度 = 速度大小,速度为 0 就看不见,所以站着时常常只剩一根。

| 看到 | 说明 |
|---|---|
| 青色比深蓝短 | 走得比要求慢 |
| 青色偏向一侧 | 边走边往旁边溜 |
| 指令为 0,青色还在乱晃 | 站不稳,或在原地踏步 |
| 被推瞬间青色突然变长、变向 | 推力造成的,看它几步内能否缩回来 |

同一面板里还有一个 `upright`(直立)开关,在平地任务里勾了也不画东西,不用管。

### Rewards(奖励)标签页:奖励条

上半部分是每一项奖励的实时条形图,约 1 秒平均一次。绿色表示在加分,红色表示在扣分,越长数值越大。下半部分 Plots(曲线)是同样这些项随时间的折线,用来看"被推的那一下哪项掉了"。Select terms(选择项)可以只勾关心的几项。

### Checkpoints(存档)标签页

下拉框切换同一 run 目录下的存档,立刻生效,不用重启。训练还在进行时点 `Sync`(同步)刷新列表。

### 标准观察流程

每个存档都按同一套步骤看,结果才能互相比:

1. Checkpoints 选存档,点 Reset Environment。
2. Twist 勾 Enable、点 Zero,站 10 秒。看它站不站得住,看奖励条。
3. 把 lin_vel_x 拉到 0.4,走 20 秒。开着速度箭头,看两根水平箭头。
4. 点 Zero,再把 ang_vel_z 拉到 0.5,转 10 秒。看两根竖直箭头。
5. 点 Zero,看它能不能停稳。
6. 遇到摔倒或怪动作,Pause,再用 Step 逐帧看;看脚的动作时用 Slower 慢放。

## 三、曲线面板:判读用法

启动方法见阶段 0 第九节。

### 两个页面:同一份数据,两种读法

页面顶部有两个标签:**SCALARS**(标量)和 **TIME SERIES**(时间序列)。它们读的是**同一批曲线数据**,区别在于怎么看、怎么读数:

| | SCALARS | TIME SERIES |
|---|---|---|
| 是什么 | 较早的页面,只放曲线 | 较新的页面,曲线、图片、直方图都放在这一页 |
| 设置在哪 | 全部摆在左侧栏,一眼看全(下一小节) | 收在右上角 Settings(设置)里,选项更多 |
| 怎么读数 | **鼠标悬停**:停在哪,黑色框就显示那一点的值 | 可以**选定某一轮**:图上出现一条竖虚线,横轴上有一个 `轮数 ×` 的小标签,每张图下方的表格显示这一轮的值 |
| 擅长 | 看**一条曲线**怎么走,读任意一点 | 同时读**很多条曲线在同一轮**的值 |
| 额外功能 | — | Pin(固定)常看的图到页面顶部;调图的宽度;选一段轮数范围 |

**为什么先用 SCALARS**:

1. **要懂的东西少。** 读数只有一个动作——鼠标停在哪就读哪;设置全在左边,不会漏看。TIME SERIES 的读数要先懂"选定一轮""按步联动"这些机制,不懂的话连表格里显示的是哪一轮都说不清。
2. **前面的练习只看一条曲线。** 练习 2–6 问的都是"这条曲线怎么走、某一点是多少",SCALARS 刚好够用。

到了诊断存档(第五节),要同时读十几条曲线在**同一轮**的值,这时换 TIME SERIES 更快,用法见本节"TIME SERIES:一次读齐同一轮"。

### 左侧设置

| 控件 | 怎么设 |
|---|---|
| Smoothing(平滑) | 看趋势用 0.6–0.9;**读某一轮的真实值时拉到 0** |
| Horizontal Axis(横轴) | 选 Step(步),一步 = 一轮 |
| Ignore outliers(忽略离群点) | 勾上,纵轴不被个别极端值撑大 |
| Runs(运行列表) | 勾选显示哪些 run,每个 run 一种颜色 |
| Tooltip sorting method(悬停框排序) | 同时看多个 run 时选 descending(降序),数值大的排上面;只看一个 run 时无所谓 |

读数:鼠标停在曲线上,悬停框里 `Value`(值)是原始值,`Smoothed`(平滑值)是平滑后的值,`Step`(步)是轮数。在图上拖一个框可以放大,双击恢复。

### 曲线分组

曲线名是"组名/项名",一共 9 组。按"在看什么"分成两类:

**看鸭子**(它学会了什么):

| 分组 | 几张图 | 看什么 |
|---|---|---|
| **Train**(训练) | 2 | `mean_episode_length` 平均回合长度(满长 1000 步);`mean_reward` 平均总分。名字带 `/time` 的是同一数据按时间画,不用看 |
| **Episode_Termination**(回合终止) | 4 | `fell_over` 和 `time_out` 各占多少。**看两者的比例,不看绝对值**;`nan_state`、`out_of_terrain_bounds` 应恒为 0(第一节) |
| **Episode_Reward**(回合奖励) | 16 | 16 项奖励各自的得分,名字和回放里的奖励条一致(第四节) |
| **Metrics**(指标) | 6 | 和奖励对应的**物理量**:走慢了多少、脚抬多高、打滑多快(第四节末尾) |
| **Episode_Metrics**(回合指标) | 1 | `mean_action_acc`:动作抖不抖(第四节末尾) |
| **Curriculum**(课程) | 7 | 课程学习每一项现在在什么水平,用来解释曲线的拐点(见下表) |

**看训练本身**(这次训练的过程健不健康,本节最后一小节):

| 分组 | 几张图 | 看什么 |
|---|---|---|
| **Policy**(策略) | 1 | `mean_std`:策略还在多大程度上"试探" |
| **Loss**(损失) | 4 | `entropy`、`learning_rate`、`value`、`surrogate`:网络更新得稳不稳 |
| **Perf**(性能) | 3 | 每一轮花了多少时间 |

`Curriculum` 组的 7 张图对应第一节第 3 条说的加码,每张图都是台阶形:

| 图 | 是什么 | 走路任务里的变化 |
|---|---|---|
| `action_rate_weight` | 动作平滑惩罚的权重 | −0.1 → −1.0,第 500–1500 轮分 5 级 |
| `standing_envs` | 拿"站着别动"指令的鸭子比例 | 0.02 → 0.25,第 500–2000 轮分 5 级 |
| `head_pose_bias_weight` | 纠正低头惩罚的权重 | 0 → 1 → 2 → 3,第 600、1000、1500 轮 |
| `head_pose_range` | 头部指令的范围(弧度) | 第 500–2000 轮逐级放宽 |
| `com_range`、`head_com_range` | 躯干、头部质心随机偏移的范围(米) | 第 500–1500 轮逐级放宽 |
| `body_pose_range` | 身体姿态指令的范围 | 一直不变(这个任务不用身体姿态指令) |

### 读曲线的七条规矩

1. **曲线贴着横轴不等于没有值。** 回合长度早期只有二三十步,在满长 1000 步的纵轴上就是一条贴地的线。悬停读值、框选放大,或者切到对数纵轴(图下方的按钮),就能看见。
2. **`Episode_Reward` 下每一项都已经乘过权重,并按 20 秒满长折算。** 所以回合越短,所有项都越小。**一大片项同时偏低时,先看回合长度和 `fell_over`**,别急着怪某一项。
3. **总分涨了不算数,主任务项 `track_linear_velocity` 自己要涨。** 否则可能只是平滑、安全这类惩罚变小了——而什么都不做,惩罚自然小。
4. **曲线在课程加码的轮数附近拐弯,先对照 `Curriculum` 组。**
5. **`mean_episode_length` 是"最近结束的 100 个回合"的平均长度。** 两个后果:
   - 第 0 轮每只鸭子只走了 24 步(一轮的长度,见阶段 0 第六节),能算进去的只有 24 步内就结束的回合,所以第 0 轮的读数天生偏短。另外训练开始时每只鸭子的回合计时被随机打散,所以第 0 轮 `time_out` 也不为 0。**最初几轮的读数不代表策略真实能撑多久。**
   - 短回合结束得勤,在这 100 个里占的份额比实际多,所以这个平均整体偏向短回合。它接近 1000,说明摔倒已经很少了。
6. **长训练的曲线是抽样画的。** 曲线面板默认每条曲线只保留 1000 个点(随机抽,最后一轮一定保留)。5 万轮的 run 平均 50 轮才留一个点,所以悬停读到的轮数是 5642、5648、5663 这样不规则的数,想读的那一轮可能根本没有。**要读某一轮的准确值,用阶段 0 第九节"保留全部数据点"的启动方式。** 只看走势时用默认方式就够了。
7. **刚打开时图可能只画了一半。** 大 run 的曲线数据要读好几分钟,这期间先显示出来的图只画到已经读到的部分(比如横轴停在七八千轮),而且之后不会自己补全。**横轴没到训练的最后一轮,就等一会儿再点右上角的刷新按钮(⟳)。** 同一页里有的图到头、有的没到头,就是这个原因,不是训练少记了。

### TIME SERIES:一次读齐同一轮

诊断 `model_2000` 时,要读回合长度、跟踪奖励、速度误差、抬脚高度……十几条曲线在第 2000 轮的值。SCALARS 里只能一张一张去悬停;TIME SERIES 可以选一次轮数,全部图一起显示。

1. 点 TIME SERIES 标签,再点右上角 Settings(设置)。
2. 勾上 Enable step selection and data table(启用选步和数据表):每张图下方出现数据表,图上出现一条竖虚线。
3. 勾上 Link by step(按步联动):所有图共用同一个选中的轮数。
4. 在任意一张图上把选中的轮数移到第 2000 轮,各图下方的表格就都显示第 2000 轮的值(推断,待核对:选轮是点击图还是拖动竖虚线,以你实际操作为准)。

两个注意:

- 这几个选项只在 Horizontal Axis(横轴)选 Step(步)时可用。
- 选中的轮数同样受第 6 条规矩的抽样影响:表格里的 Step 不一定正好是 2000,可能是附近被抽到的那一轮。**要读准确值,用"保留全部数据点"的方式启动**(阶段 0 第九节)。

### 看训练本身:Policy、Loss、Perf

前面几组回答"鸭子学会了什么";这三组回答"训练这个过程本身顺不顺"。训练过程出了问题,鸭子那边的曲线迟早也会坏,但这三组往往先露出苗头。【这三组是训练库 rsl_rl 统一记录的,换机器人、换任务也一样】

**先懂一个概念:试探。** 训练时,策略不是每次都输出它认为最好的动作,而是在上面**加一点随机扰动**,这样才能碰到"比现在更好的做法"。扰动的大小就是**动作标准差**:大 = 还在大胆试,小 = 已经比较确定该怎么做。训练的正常走向是:扰动先大后小,同时主任务项在涨。

| 曲线 | 是什么 | 正常的样子 | 要警惕的样子 |
|---|---|---|---|
| `Policy/mean_std` | 动作标准差,14 个关节的平均。起点是配置值 1.0 | 前几千轮快速下降,之后缓慢下降。本 run:第 49999 轮约 0.196 | 一直不降(学不到确定的做法);几百轮就降到很小、同时主任务项也在掉(过早不再试探) |
| `Loss/entropy` | 熵:用一个数衡量"动作有多随机"。**和 `mean_std` 说的是同一件事**,只是换了算法 | 和 `mean_std` 同步下降。**变成负数是正常的**:每个关节的熵约等于 1.42 + ln(标准差),标准差小于 0.24 时就是负的。本 run:标准差 0.196 时,14 个关节合计约 14 × (1.42 − 1.63) ≈ −3.0,读数 −3.1 | 和上一行一样。上游作者记录过一次失败实验:熵在 300 轮内从 10.9 掉到 1.9,同时 `air_time` 从 1.01 掉到 0.02,策略干脆不走路了——**熵骤降 + 主任务项掉 = 过早放弃试探** |
| `Loss/learning_rate` | 学习率:每次更新网络时改动的幅度。本任务用"自动调节":这一次改得太猛就把学习率除以 1.5,太保守就乘以 1.5(上下限 0.00001–0.01) | 在一个范围里来回跳成锯齿,这是自动调节在工作。本 run:大部分时间在约 0.00006–0.00014 之间跳 | 长期贴在下限 0.00001:每次都改得太猛,训练基本停滞 |
| `Loss/value` | 评分网络(估计"从现在起往后大概能拿多少分")的预测误差 | 平稳或缓慢下降;课程加码时跳一下是正常的。本 run:后期约 0.1–0.2 | 突然持续暴涨:奖励或环境发生了大的变化 |
| `Loss/surrogate` | 算法内部的主损失 | 在 0 附近小幅波动即可,**数值本身不用解读** | — |
| `Perf/collection_time`、`Perf/learning_time` | 每轮采样(跑仿真)和更新网络各用了几秒 | 本 run:约 2.04 秒 + 0.21 秒 ≈ 2.25 秒一轮,和阶段 0 第六节"约 2.4 秒一轮"一致。采样占了九成,瓶颈在仿真 | 某一段突然变慢:多半是同时开了回放、别的程序占了显卡 |
| `Perf/total_fps` | 每秒处理多少步经验 = 24,576 ÷ 每轮秒数 | 本 run:约 10,800 | 同上 |

**用法**:诊断一个存档之前,先扫一眼这三组,排除"训练本身出了问题"。本阶段用的两个 run 都是正常训练,这三组是用来建立"正常长什么样"的印象。

## 四、走路任务的 16 项奖励

按"管什么"分六类。权重正负和奖励 / 惩罚的关系见阶段 0 第五节;走路任务的惩罚项除 `head_pose_bias` 外都是负权重。

| 类 | 项 | 中文 | 权重 | 管什么 |
|---|---|---|---|---|
| 任务 | `track_linear_velocity` | 线速度跟踪 | +2.0 | 实际前后、横移速度离指令多远。**主任务** |
| 任务 | `track_angular_velocity` | 角速度跟踪 | +2.0 | 实际转速离指令多远 |
| 任务 | `head_pose_tracking` | 头部姿态跟踪 | +2.0 | 头部四个关节到没到指令角度 |
| 姿态 | `upright` | 直立 | +2.0 | 躯干正不正 |
| 姿态 | `pose` | 姿势 | +1.0 | 腿部关节离标准站姿多远;站着时要求严,走路时放宽 |
| 步态 | `air_time` | 腾空时间 | +3.0 | 脚每次离地后,从第 0.125 秒到第 0.3 秒这段每步给分,逼它真的迈步 |
| 步态 | `foot_clearance` | 抬脚高度 | −2.0 | 脚水平移动时,离地高度偏离 2 厘米就扣分(抬低、抬高都扣),脚移动越快扣得越多。拖着脚蹭地会被扣 |
| 步态 | `foot_swing_height` | 摆动高度 | −0.25 | 落地时检查这一步抬到的最高点,偏离 2 厘米就扣分(低了、高了都扣) |
| 步态 | `foot_slip` | 打滑 | −0.1 | 脚踩在地上还在滑 |
| 平滑 | `action_rate_l2` | 动作变化率 | −0.1 → −1.0 | 这一步和上一步的动作差多少,抖就扣分。权重随课程学习加重 |
| 平滑 | `body_ang_vel` | 躯干角速度 | −0.05 | 躯干晃得多快 |
| 平滑 | `angular_momentum` | 角动量 | −0.02 | 全身甩得多厉害 |
| 安全 | `dof_pos_limits` | 关节极限 | −1.0 | 关节顶到转动极限附近 |
| 安全 | `self_collisions` | 自碰撞 | −1.0 | 腿撞到躯干 |
| 关闭 | `body_pose_tracking` | 身体姿态跟踪 | 0 | 这个任务不用 |
| 关闭 | `head_pose_bias` | 头部偏差 | 0 → 3 | 纠正走路时头往下耷拉;随课程学习启用(见第一节)。回放开头为 0,回放累计约 14400 步(原速约 5 分钟)后才启用 |

名字里的缩写:`dof` = degree of freedom(自由度),这里就是关节;`l2` 表示按差值的平方计算;`ang_vel` = 角速度。

读奖励条时的两个要点:

- **站着时步态项全是 0**:四项步态项在指令为 0 时都不计分,这是设计,不是鸭子做错了。
- **单看一项不可信。** 比如 `air_time` 只认"脚离地的时长",鸭子翻倒时脚也离地,照样得分。先确认它站得住,再看步态项。

【分类方法和"主任务、姿态、步态、平滑、安全"这几类换机器人也一样;具体项名和权重是 microduck 的】

### Metrics:同一件事的物理量

奖励是"打了多少分",分数里混着权重、折算和曲线形状,很难还原成"鸭子实际差多少"。`Metrics` 和 `Episode_Metrics` 两组直接记**物理量**,单位是米、秒、米/秒,可以直接说出"走慢了多少、脚抬了几厘米"。

| 曲线 | 是什么(单位) | 对应的奖励项 | 往哪变算变好 | 本 run 第 49999 轮 |
|---|---|---|---|---|
| `Metrics/twist/error_vel_xy` | 实际水平速度离指令差多少,整个回合累加(见下面的注意) | `track_linear_velocity` | 变小 | 约 0.42 |
| `Metrics/twist/error_vel_yaw` | 实际转速离指令差多少,同样整个回合累加 | `track_angular_velocity` | 变小 | 约 1.15 |
| `Metrics/air_time_mean` | 正在空中的脚,平均已经离地多久(秒) | `air_time` | 会走之后保持稳定。和 `air_time` 奖励一样,翻倒时脚离地也会算进来,先确认站得住 | 约 0.12 |
| `Metrics/peak_height_mean` | 脚落地时,这一步抬到的最高点(米) | `foot_swing_height` | 接近目标 0.02 米(2 厘米) | 约 0.0125 |
| `Metrics/slip_velocity_mean` | 踩在地上的脚,水平滑动速度的平均(米/秒) | `foot_slip` | 变小 | 约 0.021 |
| `Metrics/angular_momentum_mean` | 全身转动的猛烈程度 | `angular_momentum` | 变小 | 约 0.0033 |
| `Episode_Metrics/mean_action_acc` | 动作的"加速度":连续三步的动作变化得有多急 | `action_rate_l2` | 变小 | 约 0.36(第 6692 轮读数) |

两个注意:

- **两个速度误差是"整个回合累加"的**:每一步的误差加起来,再除以 400(速度指令最长 8 秒对应的步数)。所以它和 `Episode_Reward` 一样**受回合长度影响**(第三节第 2 条),回合越短数值越小。回合基本撑满 1000 步时,**读数 ÷ 2.5 ≈ 每一步的平均误差**。本 run 第 49999 轮:水平速度平均差约 0.42 ÷ 2.5 ≈ 0.17 米/秒,转速平均差约 1.15 ÷ 2.5 ≈ 0.46 弧度/秒(推算)。
- **其余几项是每一步的直接平均,不受回合长度影响**,不同训练阶段之间可以直接比。它们统计的是全部鸭子,包括拿"站着别动"指令的那些。

【"除了打分,再记一份物理量"换机器人也一样,是设计任务时应该主动加的;具体记哪几个量是走路任务的】

## 五、诊断阶梯:按顺序问四个问题

**先排除训练本身的问题**:扫一眼 `Policy`、`Loss` 两组(第三节最后一小节)。它们异常时,先查训练过程,不用往下问。

然后按下面的顺序问。**前一个问题没过关,后面的就先不看**:鸭子站都站不住时,讨论它跟不跟得上指令没有意义。

| 顺序 | 问题 | 回放里看什么 | 曲线:得分 | 曲线:物理量 |
|---|---|---|---|---|
| 1 | **站得住吗?** | 指令为 0 时会不会倒;量一个回合多少步 | `mean_episode_length` 接近 1000 了吗;`time_out` 是否已超过 `fell_over` | — |
| 2 | **听指令吗?** | lin_vel_x = 0.4 时两根水平箭头是否重合;转向时两根竖直箭头是否重合 | `track_linear_velocity`、`track_angular_velocity` 是否在涨 | `twist/error_vel_xy`、`twist/error_vel_yaw` 是否在降,折算成平均误差是多少 |
| 3 | **步态像样吗?** | 脚是抬起来迈步,还是贴地蹭;走路时有没有滑 | `air_time` 是否为正、在涨;`foot_clearance`、`foot_slip` 的扣分是否在变小 | `peak_height_mean` 离 2 厘米多远;`slip_velocity_mean` 是否在降 |
| 4 | **细节好吗?** | 动作抖不抖;指令归零后能否站定,还是原地踏步;被推后几步稳住 | `action_rate_l2` 的扣分;对照 `Curriculum` 组看是不是刚加码 | `mean_action_acc`、`angular_momentum_mean` 是否在降 |

诊断结论的写法:**"主要问题是 X(卡在第几问),对应指标是 Y,读数是多少"**。能用物理量说的,优先用物理量。例如:"站不住,卡在第 1 问;`mean_episode_length` 约 200 步,`fell_over` 远多于 `time_out`。"或者:"会走,卡在第 3 问;脚抬得低,`peak_height_mean` 约 1.2 厘米,目标 2 厘米。"

【这四问的顺序对任何"按指令移动"的机器人都成立;第 3 问的具体指标是腿足机器人才有的】
